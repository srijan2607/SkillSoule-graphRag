## Dev Notes

### Existing Implementation Summary

The CoOccurrenceBuilder service is fully implemented with:

**Class**: `CoOccurrenceBuilder`
**Location**: `backend/app/services/co_occurrence_builder.py`

**Key Methods**:
- `build_all(clear_existing=True)` - Full rebuild of all CO_OCCURS_WITH edges
- `update_for_job(job_id)` - Incremental update for single job (for post-ingestion)
- `_is_stoplist_skill(skill_name)` - Check if skill is generic

**Relationship Schema**:
```
(:Skill)-[:CO_OCCURS_WITH {
    weight: INTEGER,     -- Number of jobs requiring BOTH skills
    cost: FLOAT,         -- 1.0 / weight (for Dijkstra shortest path)
    created_at: DATETIME,
    updated_at: DATETIME
}]-(:Skill)
```

**Configuration** (from `app/config.py`):
- `NETWORK_MIN_CO_OCCURRENCE`: Minimum weight threshold (default: 2)
- `NETWORK_GENERIC_SKILLS_STOPLIST`: List of generic skills to exclude

[Source: backend/app/services/co_occurrence_builder.py]

### Technical Notes

1. **Edge Direction**: CO_OCCURS_WITH is bidirectional (created once per pair using `id(s1) < id(s2)`)
2. **Cost Formula**: `cost = 1.0 / weight` (lower weight = higher cost = longer path)
3. **Stoplist Skills**: Generic skills like "Communication", "Teamwork", "MS Excel" are excluded
