# Story 7.1: Schema Migration & Skill Normalization

## Status

**Completed**

## Story

**As a** system administrator,
**I want** skill names normalized to canonical forms with proper alias mappings,
**so that** duplicate skills are merged and data quality improves for downstream analytics.

## Acceptance Criteria

1. SkillNormalizer handles all alias mappings (JS→javascript, C#→csharp, .NET→dotnet, etc.)
2. SkillNormalizer preserves display names while computing canonical names
3. Migration script runs in correct order: normalize → dedupe → constraint
4. UNIQUE constraint on `canonical_name` added AFTER deduplication
5. Verification query returns empty: `MATCH (s:Skill) WITH s.canonical_name as cn, count(*) as c WHERE c > 1 RETURN cn, c`
6. All unit tests pass for SkillNormalizer

### Technical Constraints

1. **Migration Order is NON-NEGOTIABLE**:
   ```
   STEP 1: Apply SkillNormalizer to update canonical_name
   STEP 2: Deduplicate skills (merge by canonical_name)
   STEP 3: Create UNIQUE constraint on canonical_name
   ```

   Rationale: Constraint creation will FAIL if duplicates exist.

2. **Alias Mapping Source of Truth**:
