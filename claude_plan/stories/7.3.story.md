## Dev Notes

### Existing Implementation Summary

The JobSimilarityBuilder service is implemented with:

**Class**: `JobSimilarityBuilder`
**Location**: `backend/app/services/job_similarity_builder.py`

**Key Methods**:
- `build_all(clear_existing=True)` - Full rebuild of SIMILAR_JOB edges
- `update_for_job(job_id)` - Incremental update for single job
- `get_statistics()` - Get relationship statistics

**Relationship Schema**:
```
(:Job)-[:SIMILAR_JOB {
    jaccard_score: FLOAT,      -- |shared_skills| / |union_skills|
    shared_count: INTEGER,     -- Number of shared skills
    computed_at: DATETIME
}]->(:Job)
```

**Constructor Parameters**:
- `min_shared_skills`: Minimum shared skills (default: 3)
- `min_jaccard`: Minimum Jaccard score (default: 0.2)
- `max_similar_per_job`: Maximum similar jobs per job (default: 20)

[Source: backend/app/services/job_similarity_builder.py]

### Algorithm

**Jaccard Similarity**:
```
jaccard(Job_A, Job_B) = |Skills_A ∩ Skills_B| / |Skills_A ∪ Skills_B|
```

**Filtering**:
- Only create relationship if `shared_count >= min_shared_skills`
- Only create relationship if `jaccard_score >= min_jaccard`
- Keep top `max_similar_per_job` most similar jobs per job

### GDS vs Fallback

- **GDS nodeSimilarity**: Preferred for full rebuilds (O(n) complexity)
- **Fallback update_for_job()**: Works without GDS for incremental updates
