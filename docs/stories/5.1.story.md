## Story
**As a** user
**I want** a clean chat interface to interact with the system
**so that** I can ask questions naturally

## Acceptance Criteria
1. Chat page created at `/chat` route (protected)
2. Chat layout: Message list (scrollable) + Input field (bottom)
3. Message components: UserMessage (right-aligned) and AssistantMessage (left-aligned)
4. Input field with "Send" button and Enter key support
5. Typing indicator shown while waiting for LLM response
6. Auto-scroll to bottom when new messages appear
7. Message history persisted in React state (cleared on page refresh)
8. Clean, minimal UI with clear visual distinction between user and assistant messages
9. Timestamps displayed for each message (optional, can be hidden for MVP)
10. Empty state: "Ask me anything about careers, skills, or jobs!"

  {/* Message List - Scrollable */}

### Styling Guidelines
- **User messages**:
  - Align right, max-width 70%, margin-left auto
  - Background: blue-500 or primary color
  - Text: white
  - Border radius: rounded corners
- **Assistant messages**:
  - Align left, max-width 70%, margin-right auto
  - Background: gray-100 or neutral
  - Text: gray-900
  - Border radius: rounded corners
- **Spacing**: Consistent margins between messages (e.g., 16px)
- **Timestamps**: Small text, gray-500, optional (can toggle visibility)

- Semantic HTML: Use `<main>`, `<section>`, `<button>` tags
- ARIA labels: `aria-label="Send message"` on send button
- Keyboard navigation: Tab through input and button, Enter to send
- Focus states: Clear visual focus indicators

## Code Quality Assessment

### ✅ Strengths

1. **Clean Architecture**: Excellent component separation with single responsibility
2. **Comprehensive Testing**: 33 Chat-specific tests (all passing) out of 148 total tests
3. **PropTypes Validation**: All components have proper runtime type checking
4. **Accessibility Basics**: ARIA labels present on interactive elements
5. **Keyboard Support**: Full keyboard navigation (Enter to send, Shift+Enter for newline)
6. **State Management**: Clean useState pattern for message history
7. **Auto-scroll UX**: Smooth scrolling behavior on message updates
8. **Responsive Design**: Max-width constraints and flexible layouts
9. **Protected Routes**: Proper authentication guards via ProtectedRoute component

### ⚠️ Concerns (Medium Priority)

1. **Type Safety Gap**
   - **Issue**: Components are `.jsx` not `.tsx` despite TypeScript being in tech stack
   - **Evidence**: Types defined in `frontend/src/types/chat.ts` but not used in components
   - **Impact**: Missing compile-time type safety, intellisense benefits, type errors possible at runtime
   - **Recommendation**: Convert components to TypeScript for type safety

2. **Accessibility Gaps**
   - **Issue**: No ARIA live regions for dynamic message updates
   - **Missing**: `role="log"` on message container, `aria-live="polite"` for screen readers
   - **Missing**: Screen reader announcement when typing indicator appears
   - **Impact**: Screen reader users may not be notified of new messages
   - **Recommendation**: Add ARIA live regions and semantic roles

3. **Performance Considerations**
   - **Issue**: No memoization on message components
   - **Evidence**: UserMessage and AssistantMessage re-render on every message addition
   - **Issue**: No virtualization for long message lists
   - **Impact**: Performance degradation with 100+ messages (full re-render)
   - **Recommendation**: Add React.memo() to message components, consider virtualization

4. **Testing Coverage Gaps**
   - **Issue**: No E2E tests with Playwright despite frontend focus
   - **Evidence**: Playwright installed (`@playwright/test` in devDependencies) but no E2E tests created
   - **Issue**: Auto-scroll tested only via mocks, not actual behavior
   - **Issue**: No accessibility tests with axe-core (despite `@axe-core/playwright` installed)
   - **Recommendation**: Add E2E tests for critical user flows, accessibility validation

5. **UX Polish Opportunities**
   - Textarea doesn't auto-resize (fixed height can be limiting)
   - No character count indicator
   - Send button shows no loading animation (just disabled state)
   - Placeholder setTimeout could be better documented as temporary
