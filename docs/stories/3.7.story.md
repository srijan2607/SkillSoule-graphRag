# Story 3.7: Incremental Update & Upsert Logic

## Status

**Approved**

## Story

**As a** system,
**I want** to handle weekly CSV re-uploads without duplicating data,
**so that** users can update the graph with new data

## Acceptance Criteria

1. Node creation uses MERGE instead of CREATE (upsert by unique ID: Job ID, Skill ID, Company Name)
2. MERGE pattern: `ON CREATE SET` for initial creation, `ON MATCH SET` for updates
3. On match: Update all node properties with new CSV values (embeddings, metadata, timestamps)
4. Relationship handling: Delete existing relationships for updated nodes, create new ones from CSV
5. Example: If Job 123 previously required [Python, Java], new CSV says [Python, React], result is [Python, React]
6. Orphan relationship cleanup: Neo4j `DETACH DELETE` automatically removes relationships to deleted nodes
7. Ingestion mode flag: "full" (delete all, recreate) vs "incremental" (upsert only)
8. Default mode: "incremental" (safer for production)
9. Full mode requires explicit user confirmation to prevent accidental data loss
10. Full mode warning: "This will delete ALL existing graph data. Type 'CONFIRM DELETE' to proceed."
11. Update tracking: `created_at` (never changes), `updated_at` (set on every MERGE match)
12. Version comparison: Skip update if CSV row unchanged (compare hash of all fields)

### MERGE Pattern Implementation

**MERGE with ON CREATE SET and ON MATCH SET:**

```cypher
-- Skill node upsert
MERGE (s:Skill {id: $id})
ON CREATE SET
  s.name = $name,
  s.level = $level,
  s.description = $description,
  s.embedding = $embedding,
  s.row_hash = $row_hash,
  s.created_at = datetime()
ON MATCH SET
  s.name = $name,
  s.level = $level,
  s.description = $description,
  s.embedding = $embedding,
  s.row_hash = $row_hash,
  s.updated_at = datetime()
RETURN s.id as id,
       CASE WHEN s.created_at = datetime() THEN 'created' ELSE 'updated' END as action
```

**Key Points:**
- `created_at` only set on CREATE, never on MATCH
- `updated_at` only set on MATCH (property doesn't exist for newly created nodes)
- Return `action` to track whether node was created or updated

### Relationship Cleanup Strategy

**Problem:** If Job 123 previously required [Python, Java], and new CSV says [Python, React], we need to remove the old Python→Java relationships and create Python→React.

**Solution:** Delete all REQUIRES relationships for a job before recreating from CSV.

**Create `backend/app/services/relationship_cleanup_service.py`:**

```python
"""Relationship cleanup service for incremental updates."""
import logging

logger = logging.getLogger(__name__)

class RelationshipCleanupService:
    """
    Cleanup existing relationships before re-creating from CSV.

    Ensures job-skill relationships match current CSV state, not
    accumulated relationships from previous uploads.
    """

    def __init__(self, neo4j_repo):
        self.neo4j_repo = neo4j_repo

    async def delete_job_skill_relationships(self, job_ids: list[str]) -> int:
        """
        Delete all REQUIRES relationships for given jobs.

        Args:
            job_ids: List of Job IDs to clean

        Returns:
            int: Number of relationships deleted

        Called before re-creating REQUIRES relationships from CSV
        to ensure clean state.
        """
        query = """
        MATCH (j:Job)-[r:REQUIRES]->(:Skill)
        WHERE j.job_id IN $job_ids
        DELETE r
        RETURN count(r) as deleted_count
        """

        result = await self.neo4j_repo.execute_query(
            query,
            {"job_ids": job_ids}
        )

        deleted_count = result[0]["deleted_count"] if result else 0

        logger.info(
            f"Deleted {deleted_count} REQUIRES relationships "
            f"for {len(job_ids)} jobs (cleanup before re-ingestion)"
        )

        return deleted_count

    async def delete_all_skill_relationships(self, skill_ids: list[str]) -> int:
        """
        Delete all relationships for given skills.

        Args:
            skill_ids: List of Skill IDs to clean

        Returns:
            int: Number of relationships deleted

        Used when re-ingesting skills taxonomy to ensure
        BELONGS_TO_CATEGORY and SIMILAR_TO relationships are fresh.
        """
        query = """
        MATCH (s:Skill)-[r]-()
        WHERE s.id IN $skill_ids
        DELETE r
        RETURN count(r) as deleted_count
        """

        result = await self.neo4j_repo.execute_query(
            query,
            {"skill_ids": skill_ids}
        )

        deleted_count = result[0]["deleted_count"] if result else 0

        logger.info(
            f"Deleted {deleted_count} relationships "
            f"for {len(skill_ids)} skills (cleanup before re-ingestion)"
        )

        return deleted_count
```

        json_schema_extra = {
            "example": {
                "mode": "incremental"
            }
        }

from fastapi import APIRouter, UploadFile, File, Depends, HTTPException, status
from app.models.ingestion_mode import IngestionMode, IngestionJobRequest
from app.services.ingestion_service import IngestionService
from app.middleware.auth import get_current_user

router = APIRouter(prefix="/api/ingest", tags=["ingestion"])

@router.post("/skills", response_model=IngestionJobResponse, status_code=status.HTTP_202_ACCEPTED)
async def upload_skills_csv(
    file: UploadFile = File(...),
    mode: IngestionMode = IngestionMode.INCREMENTAL,
    confirmation: Optional[str] = None,
    current_user: str = Depends(get_current_user),
    ingestion_service: IngestionService = Depends()
):
    """
    Upload and process skills taxonomy CSV.

    Args:
        file: CSV file with skills taxonomy
        mode: "incremental" (upsert) or "full" (delete all + recreate)
        confirmation: Must be "CONFIRM DELETE" if mode is "full"
        current_user: Authenticated user ID

    Raises:
        400: If full mode without confirmation
        400: If confirmation text incorrect
    """
    # Validate full mode confirmation
    if mode == IngestionMode.FULL:
        if not confirmation or confirmation != "CONFIRM DELETE":
            raise HTTPException(
                status_code=status.HTTP_400_BAD_REQUEST,
                detail=(
                    "Full mode requires explicit confirmation. "
                    "Set confirmation='CONFIRM DELETE' to proceed. "
                    "WARNING: This will delete ALL existing graph data."
                )
            )

        logger.warning(
            f"⚠️  FULL MODE INGESTION initiated by user {current_user}. "
            f"All graph data will be deleted."
        )

    return await ingestion_service.start_skills_ingestion(
        file,
        current_user,
        mode=mode
    )

### Full Mode Implementation

**Create `backend/app/services/graph_deletion_service.py`:**

```python
"""Graph data deletion service for full refresh mode."""
import logging

logger = logging.getLogger(__name__)

class GraphDeletionService:
    """
    Delete all graph data for full refresh ingestion.

    WARNING: Destructive operation, requires explicit user confirmation.
    """

    def __init__(self, neo4j_repo):
        self.neo4j_repo = neo4j_repo

    async def delete_all_nodes_and_relationships(self) -> dict:
        """
        Delete ALL nodes and relationships from Neo4j.

        Returns:
            dict: {
                "nodes_deleted": int,
                "relationships_deleted": int
            }

        WARNING: Irreversible operation. Ensure backup exists.

        Cypher DETACH DELETE:
        - DETACH removes all relationships connected to nodes
        - Then deletes the nodes themselves
        - Single atomic operation
        """
        logger.warning("🚨 Deleting ALL graph data (FULL MODE)")

        query = """
        MATCH (n)
        WITH n, count{(n)-[r]-()} as rel_count
        DETACH DELETE n
        RETURN count(n) as nodes_deleted, sum(rel_count) as relationships_deleted
        """

        result = await self.neo4j_repo.execute_query(query)

        stats = {
            "nodes_deleted": result[0]["nodes_deleted"] if result else 0,
            "relationships_deleted": result[0]["relationships_deleted"] if result else 0
        }

        logger.warning(
            f"🗑️  Graph deletion complete: "
            f"{stats['nodes_deleted']} nodes, "
            f"{stats['relationships_deleted']} relationships removed"
        )

        return stats
```

### Hash-Based Change Detection

**Create `backend/app/utils/hash_utils.py`:**

```python
"""Hash utilities for change detection in incremental updates."""
import hashlib
import json
from typing import Dict, Any

def compute_row_hash(row_dict: Dict[str, Any]) -> str:
    """
    Compute SHA256 hash of CSV row for change detection.

    Args:
        row_dict: CSV row as dictionary

    Returns:
        str: SHA256 hash (hex string)

    Excludes from hash:
    - created_at, updated_at (metadata)
    - embedding (always regenerate)
    - row_hash (circular dependency)

    Purpose:
    - Skip update if hash unchanged (no data changes)
    - Save embedding generation cost for unchanged rows
    """
    # Exclude metadata fields
    excluded_fields = {"created_at", "updated_at", "embedding", "row_hash"}

    # Create sorted dict for consistent hashing
    hashable_data = {
        k: v for k, v in sorted(row_dict.items())
        if k not in excluded_fields
    }

    # Serialize to JSON (deterministic order)
    json_str = json.dumps(hashable_data, sort_keys=True, ensure_ascii=False)

    # Compute SHA256 hash
    hash_obj = hashlib.sha256(json_str.encode("utf-8"))
    return hash_obj.hexdigest()

def has_row_changed(new_row: Dict[str, Any], existing_hash: str) -> bool:
    """
    Check if CSV row has changed since last ingestion.

    Args:
        new_row: New CSV row data
        existing_hash: Hash from existing Neo4j node

    Returns:
        bool: True if row changed, False if unchanged
    """
    new_hash = compute_row_hash(new_row)
    return new_hash != existing_hash
```

### Updated SkillGraphService with Upsert

**Update `backend/app/services/skill_graph_service.py`:**

```python
async def _create_skill_node(self, tx, skill_row: dict, embedding_data: dict) -> str:
    """
    Upsert skill node using MERGE.

    Returns:
        str: "created" | "updated" | "unchanged"
    """
    from app.utils.hash_utils import compute_row_hash

    # Compute row hash
    row_hash = compute_row_hash(skill_row)

    # Check if node exists with same hash (no changes)
    check_query = """
    MATCH (s:Skill {id: $id})
    RETURN s.row_hash as existing_hash
    """

    existing = await tx.run(check_query, {"id": skill_row["ID"]})
    existing_record = await existing.single()

    if existing_record and existing_record["existing_hash"] == row_hash:
        # No changes detected, skip update
        return "unchanged"

    # Upsert with MERGE
    query = """
    MERGE (s:Skill {id: $id})
    ON CREATE SET
      s.name = $name,
      s.level = $level,
      s.type = $type,
      s.is_software = $is_software,
      s.is_language = $is_language,
      s.description = $description,
      s.wiki_link = $wiki_link,
      s.wiki_extract = $wiki_extract,
      s.embedding = $embedding,
      s.embedding_model_version = $embedding_model_version,
      s.embedding_generated_at = $embedding_generated_at,
      s.row_hash = $row_hash,
      s.created_at = datetime()
    ON MATCH SET
      s.name = $name,
      s.level = $level,
      s.type = $type,
      s.is_software = $is_software,
      s.is_language = $is_language,
      s.description = $description,
      s.wiki_link = $wiki_link,
      s.wiki_extract = $wiki_extract,
      s.embedding = $embedding,
      s.embedding_model_version = $embedding_model_version,
      s.embedding_generated_at = $embedding_generated_at,
      s.row_hash = $row_hash,
      s.updated_at = datetime()
    RETURN CASE
      WHEN s.created_at = datetime() THEN 'created'
      ELSE 'updated'
    END as action
    """

    result = await tx.run(query, {
        "id": skill_row["ID"],
        "name": skill_row["NAME"],
        "level": skill_row.get("LEVEL"),
        "type": skill_row.get("TYPE"),
        "is_software": skill_row.get("IS_SOFTWARE"),
        "is_language": skill_row.get("IS_LANGUAGE"),
        "description": skill_row.get("DESCRIPTION"),
        "wiki_link": skill_row.get("WIKI_LINK"),
        "wiki_extract": skill_row.get("WIKI_EXTRACT"),
        "embedding": embedding_data["embedding"],
        "embedding_model_version": embedding_data["model_version"],
        "embedding_generated_at": embedding_data["generated_at"],
        "row_hash": row_hash
    })

    record = await result.single()
    return record["action"]
```

### Refactoring Performed

#### 1. Fixed Critical Bug in Graph Deletion Service

**File**: `backend/app/services/graph_deletion_service.py`

**Change**: Fixed incorrect relationship counting logic in `delete_all_nodes_and_relationships()`

**Why**: The original implementation used `sum(rel_count)/2` which is mathematically incorrect. In Neo4j, `count{(n)-[r]-()}` counts relationships from each node's perspective, so dividing by 2 attempts to handle bidirectional counting. However, this approach is flawed because:
1. Not all relationships are bidirectional
2. The count aggregation may not behave as expected with division
3. The query was attempting to count and delete in a single operation, making it unreliable

**How**: Split into two operations:
1. First query: Count all distinct relationships using `MATCH ()-[r]-() RETURN count(DISTINCT r)`
2. Second query: Delete all nodes with `DETACH DELETE` and return node count
3. This ensures accurate relationship counting before deletion occurs

**Impact**: Critical correctness fix - statistics now accurately reflect actual deletions

**Code Changes**:
```python
# BEFORE (incorrect):
query = """
MATCH (n)
WITH n, count{(n)-[r]-()} as rel_count
DETACH DELETE n
RETURN count(n) as nodes_deleted, sum(rel_count)/2 as relationships_deleted
"""

# AFTER (correct):
count_query = """
MATCH ()-[r]-()
RETURN count(DISTINCT r) as rel_count
"""
# ... count relationships first, then delete nodes
```
