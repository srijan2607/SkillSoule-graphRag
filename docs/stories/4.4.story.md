# Story 4.4: Graph Traversal Node

## Status

**Done** (QA Fixes Applied - Awaiting Re-Review)

## Story
**As a** system
**I want** to explore relationships from vector search results
**so that** I can retrieve rich contextual information

## Acceptance Criteria
1. Node receives `vector_results` and `query_intent` from state
2. Generate Cypher query based on intent:
   - **skill_requirement**: Start from Job nodes, traverse `Job -[REQUIRES]-> Skill`, include skill categories
   - **career_path**: Start from Skill nodes, traverse `Skill -[SIMILAR_TO]-> Skill` and `Skill <-[REQUIRES]- Job`
   - **salary_analysis**: Start from Job nodes, include salary properties, traverse to Skills and Companies
   - **skill_relationship**: Start from Skill nodes, traverse `Skill -[SIMILAR_TO]-> Skill` and categories
   - **company_query**: Start from Company or Job nodes, traverse `Job -[POSTED_BY]-> Company` and `Job -[REQUIRES]-> Skill`
3. Traversal depth: 2-3 hops from seed nodes (configurable)
4. Collect all traversed nodes and relationships
5. Return structured graph context: `{nodes: [...], relationships: [...]}`
6. Update state: `{graph_results: {nodes, relationships}}`
7. Limit total nodes returned to prevent context overflow (max 50 nodes)

### Cypher Query Examples
```cypher
// skill_requirement intent
MATCH (j:Job) WHERE j.job_id IN $seed_job_ids
MATCH (j)-[req:REQUIRES]->(s:Skill)
OPTIONAL MATCH (s)-[:BELONGS_TO_CATEGORY]->(cat:Category)
OPTIONAL MATCH (s)-[:BELONGS_TO_SUBCATEGORY]->(sub:Subcategory)
RETURN j, req, s, cat, sub
LIMIT 50

// career_path intent
MATCH (s:Skill) WHERE s.id IN $seed_skill_ids
OPTIONAL MATCH (s)-[sim:SIMILAR_TO]-(similar:Skill)
OPTIONAL MATCH (j:Job)-[req:REQUIRES]->(s)
OPTIONAL MATCH (s)-[:BELONGS_TO_CATEGORY]->(cat:Category)
RETURN s, sim, similar, j, req, cat
LIMIT 50

// salary_analysis intent
MATCH (j:Job) WHERE j.job_id IN $seed_job_ids
MATCH (j)-[:REQUIRES]->(s:Skill)
MATCH (j)-[:POSTED_BY]->(c:Company)
RETURN j.salary_min, j.salary_max, j.salary_currency, s, c
ORDER BY j.salary_max DESC
LIMIT 50
```

### Critical Implementation Notes
1. **Intent routing**: Use match/case or dict mapping to select traversal query
2. **Seed nodes**: Extract node IDs from top vector_results (top 5-10)
3. **Depth control**: Use variable-length patterns in Cypher `[*1..2]` or `[*1..3]`
4. **Node deduplication**: Multiple paths may return same nodes, deduplicate by ID
5. **Relationship metadata**: Include similarity_score from REQUIRES relationships
6. **Performance**: Use `LIMIT` aggressively to avoid slow queries
